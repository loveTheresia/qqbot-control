# 人格蒸馏方案（Phase 1）

## 目标

用现有真实聊天记录，提炼她“怎么说话、持什么观点、哪些话不能说”，产出一份可审阅的角色卡草稿。

**这一轮不是微调模型，不更新权重，不覆盖线上人格。**
“训练”在这里指：从日志里蒸馏出 voice / stance / examples，后续再决定是否注入。

## 为什么先蒸馏，不直接 fine-tune

| 方案 | 成本 | 风险 | 现在是否做 |
|---|---|---|---|
| Prompt + 检索 + 示例 | 低 | 可回滚、可审阅 | ✅ 本轮 |
| LoRA/微调 | 中高 | 会把旧毛病、过时梗、错误事实一起学进去 | ❌ 暂不做 |
| 继续堆长 system prompt | 低 | 越长越容易漂，注意力被稀释 | ❌ 不推荐 |

现有日志里她自己的回复占很大比例，直接拿去微调，会把“接话过频、短回复、偶尔不懂装懂”一起固化。所以先做**筛选后的蒸馏**。

## 数据审计

当前真实数据：

- 私聊主人：约 194 条消息；
- 主群：约 373 条群员消息、183 条她的发言；
- 她的回复大量在 8 字以内；群聊回复多在 15~29 字；
- 话题高度集中在 LPL、原神/鸣潮、火影手游、单机游戏。

结论：

1. 这批日志能学**群聊语气、游戏/LPL 观点、吐槽方式**；
2. 学不到“知书达理”，因为日志里几乎没有读书、历史、文学、社会议题的深度讨论；
3. 旧日志包含“接话过频”的坏习惯，只能选有上下文的回复做示例，不能按频率学。

## 蒸馏流水线

```text
真实日志
  → 只取主人私聊 + 主群，排除测试会话
  → 配对「触发消息 + 她的回复 + 前文」
  → 过滤命令、AI 自曝、搜索失败、元对话、脏话、重复
  → 质量打分（长度、是否有人接话、是否回答问题）
  → LLM 提炼 voice / traits / stances / interests / boundaries
  → 从真实样本里选 6~8 条示例（不让模型自造）
  → 产出草稿，人工审阅后才注入
```

## 产出物

- `persona/distill-*.json`：原始样本 + 模型分析；
- `persona/card.draft.md`：人可读的角色卡草稿；
- `persona/examples.draft.jsonl`：从真实记录选出的示例对话；
- `config/system_prompt.txt`：**未修改**。

## 下一轮要补的

### 1. 分语域

这轮把群聊和私聊混在一起分析，导致“句长中等偏长”的判断其实偏私聊。下一版要分开：

- `voice_group`：短、接梗、少解释；
- `voice_private`：可以多一句背景，但不写论文；
- `voice_serious`：认真回答时先结论、再理由，不掉书袋。

### 2. 立场核实

蒸馏出的立场里有比分、赛果、版本、评分等时效信息，不能直接当永久设定。需要标注：

```json
{"stance": "...", "confidence": 0.8, "volatile": true, "verified_at": "..."}
```

### 3. 知书达理层

日志给不了这个，需要单独建 `canon`：

- 100~200 个作品/概念/人物；
- 每条：背景、核心观点、常见误读、可引用程度、关联主题；
- 引文必须核实；
- 只在相关话题触发，不常驻。

### 4. 结构化角色卡

把草稿整理成 V2 风格：

```text
identity / values / voice / behaviors / boundaries
scenario / examples / worldbook / post_history_instructions
```

身份和底线仍以 `config/system_prompt.txt` 为唯一真相，蒸馏结果只能补充，不能覆盖。

### 5. 注入顺序

```text
人格核心（不可变）
→ 角色卡（属性/行为/边界）
→ 世界书命中条目
→ 长期记忆/成员画像
→ 示例对话（few-shot）
→ 最近群聊
→ 当前场景指令
```

## 安全边界

- 不把群友隐私写进角色卡；
- 不把“别人说的观点”写成“她的立场”；
- 不把一次性玩笑写成稳定特征；
- 不把过时赛果/版本当永久事实；
- 不因为蒸馏结果改变“被 @ 才详回、群聊少插话”的规则。

## 这一轮的结论

现有日志足够做**第一版 voice 和游戏/LPL 观点卡**，但不足够做“知书达理”。
先把这版草稿审掉，再决定是否注入；评测按你的要求后置。
